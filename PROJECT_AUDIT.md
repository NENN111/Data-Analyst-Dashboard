## Архитектура

1. `trudvsem_etl.py` получает страницы вакансий из API «Работа России».
2. `superjob_etl.py` загружает открытые вакансии через официальный API SuperJob при наличии `SUPERJOB_API_KEY`.
3. Заголовки фильтруются по аналитическим ролям, а поля источников приводятся к единой схеме.
4. ID вместе с именем источника преобразуется в стабильный положительный `BIGINT`.
5. `db.py` создаёт таблицу и выполняет PostgreSQL UPSERT по первичному ключу.
6. `app.py` читает данные небольшими страницами, применяет фильтры и строит метрики, графики и таблицы.
7. `.github/workflows/daily_etl.yml` запускает обновление ежедневно; шаг SuperJob пропускается, пока секрет не настроен.

Навыки сохраняются как JSON-массив. Зарплата для графиков оценивается серединой вилки; если указана только одна граница, используется она. В агрегаты попадают только значения с валютой `RUR`.

## Устойчивость соединения

Внешнее подключение Render периодически закрывало длинные запросы. Сейчас используются:

- `NullPool`, чтобы закрытые соединения не возвращались из пула;
- AUTOCOMMIT для независимых операций;
- до трёх попыток записи текущей вакансии с переподключением;
- до трёх попыток SELECT-запроса;
- чтение дашборда страницами по пять строк.

На проверенной выборке эти меры устранили ошибки интерфейса и позволили завершить полную загрузку. Первый показ данных может занимать несколько секунд из-за внешнего соединения; затем результат хранится в кэше Streamlit пять минут.

## Открытые вопросы и ограничения

### 1. GitHub Actions secret настроен

Actions secret `DATABASE_URL` создан в репозитории через GitHub CLI 10.09.2026. В нём хранится External Database URL базы Render; значение секрета не выводилось в терминал и не добавлялось в Git.

### 2. Выборка не описывает весь рынок

ETL загружает до пяти страниц результатов запроса и дополнительно фильтрует названия вакансий. Это практическая выборка для дашборда, а не полная статистика рынка труда.

### 3. Старые вакансии не архивируются

UPSERT добавляет и обновляет записи, но не помечает исчезнувшие вакансии закрытыми. Для анализа только активных вакансий нужны поля `first_seen_at`, `last_seen_at`, `is_active` и отдельная процедура архивирования.

### 4. Методика зарплаты приблизительная

Источник не предоставляет единый признак gross/net для всех записей, поэтому `salary_gross` остаётся пустым. Середина вилки является оценкой предложения, а не фактической зарплатой сотрудника.

### 5. Нет полноценного набора автотестов и миграций

В репозитории нет pytest-тестов, проверки на push/PR, lock-файла и инструмента миграций схемы. `create_all()` подходит текущему прототипу, но не заменяет Alembic при изменении таблиц.

### 6. Исторические имена Render требуют отдельной миграции

Локальные шаблоны `docker-compose.yml` и `.env.example` используют нейтральные имена `data-analyst-postgres` и `vacancies_analytics`. Исторические идентификаторы в `render.yaml` сохранены, потому что они привязаны к существующим Render-ресурсам. `databaseName` и `user` у созданной Render Postgres неизменяемы; полное переименование требует новой базы, переноса данных и контролируемого переключения `DATABASE_URL`.
