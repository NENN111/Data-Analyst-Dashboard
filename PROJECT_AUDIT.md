## Проблемы по приоритету

### 1. Высокий: ежедневный ETL на GitHub падает

Все 6 запусков с 4 по 9 сентября 2026 имеют статус `failure`.
В последнем запуске checkout, настройка Python и установка зависимостей успешны;
падает шаг `Load fresh HH.ru vacancies`, код завершения 1.

[Последний запуск](https://github.com/NENN111/Data-Analyst-Dashboard/actions/runs/34325612522).

Полные логи через неавторизованный GitHub API возвращают HTTP 403.
Поэтому причина — подключение к БД, настройка секрета, API или другое — не установлена.
Первое действие: прочитать traceback этого шага и проверить `DATABASE_URL` в настройках Actions.
Само значение секрета для отчёта не требуется.

### 2. Высокий: фильтры скрывают записи с NULL

`app.py:46–59`: варианты фильтров строятся через `dropna()`, затем применяется `isin()`.
Даже выбор всех предложенных значений исключает записи, где город, опыт или график не заполнены.
В тесте из 6 записей осталось 3, хотя пользователь ничего не исключал.
Это меняет число вакансий, зарплатную статистику и долю удалёнки.

Нужно отображать пропуски как «Не указан» либо сохранять их при выборе всех значений.

### 3. Высокий: загрузчик недостаточно устойчив к ошибкам API

`etl.py:23–28,63–70`:

- Ошибка поискового запроса немедленно завершает загрузку; повторных попыток нет.
  Поскольку запись в БД происходит только после завершения сбора, уже собранный пакет не сохраняется.
- Ошибки запросов деталей только печатаются; соответствующие вакансии пропускаются.
- Воспроизведён полный отказ запросов деталей: `main()` вывел «Загружено и обновлено вакансий: 0»
  и завершился успешно. Такой запуск может быть зелёным в Actions без обновления данных.

Нужны ограниченные повторные попытки при временных сбоях, учёт ошибок и неуспешный статус
при полном отказе загрузки. При частичной загрузке следует явно показывать её результат.

### 4. Средний: дубли ID внутри пакета обрушивают UPSERT

`db.py:68–80`: два одинаковых ID в одном вызове воспроизводимо приводят к
`CardinalityViolation: ON CONFLICT DO UPDATE command cannot affect row a second time`.
Транзакция пакета откатывается. Повторные отдельные запуски работают правильно.
Нужно устранить повторы ID до формирования INSERT. Наличие дублей в живых ответах HH не подтверждено.

### 5. Средний: первый запуск не доведён до готового интерфейса

- Без `DATABASE_URL` импорт `db.py:34` вызывает необработанное исключение до блока
  обработки ошибок в приложении. Даже `python etl.py --help` падает.
- В свежей БД без таблицы приложение показывает ошибку SQL. Таблицу создаёт только ETL.
  Команда запуска Render не инициализирует схему. Поэтому первый деплой до успешного ETL
  не показывает пустой рабочий дашборд.

Нужны отдельная инициализация схемы при развёртывании и понятное сообщение об отсутствии настройки.

### 6. Средний: данные не отражают гарантированно актуальный рынок

`etl.py` только добавляет и обновляет найденные вакансии. Нет признака архивирования,
времени последнего наблюдения и механизма актуализации исчезнувших из поиска вакансий.
Ранее загруженные записи продолжают попадать в показатели.
По умолчанию собирается максимум 500 результатов поиска, а не весь рынок.
В интерфейсе нет даты последней успешной загрузки или явного описания охвата выборки.

### 7. Средний: зарплаты до и после налогов смешиваются

`salary_gross` сохраняется, но не участвует в фильтрах, показателях и SQL-агрегации.
Рублёвые суммы до и после налогов считаются вместе и не различаются в таблице.
Кроме того, для каждой вакансии берётся середина вилки или единственная граница;
это оценка предложенной зарплаты, а не наблюдаемая фактическая зарплата.
Нужно обозначить методику и разделить категории gross/net.

### 8. Средний: бесплатная БД ограничивает срок работы Render

`render.yaml:20` использует `plan: free` для PostgreSQL. По актуальной документации Render
такая БД становится недоступной через 30 дней; после 14-дневного периода для перехода
на платный план удаляется вместе с данными. Платный веб-сервис это ограничение не отменяет.

[Ограничения Render Free Postgres](https://render.com/docs/free#free-postgres).

План веб-сервиса `0.5c-512mb` является допустимым согласно
[спецификации Blueprint](https://render.com/docs/blueprint-spec); ошибки в его названии нет.
Фактическое состояние сервиса в аккаунте Render не проверено.

### 9. Низкий: воспроизводимость и автоматические проверки

- В репозитории нет тестов и CI-проверок на push/PR; есть только ежедневный ETL.
- Зависимости ограничены снизу, lock-файла нет; версии при установке могут меняться.
- Версия Python задана в Actions, но не закреплена для Render и локального запуска.
- Streamlit выдаёт предупреждения об устаревшем `use_container_width`.
- GitHub сообщает о старых Node.js action-версиях checkout/setup-python;
  в последнем запуске эти шаги успешны, причиной зафиксированного сбоя они не являются.
- `create_all()` не заменяет миграции при будущих изменениях схемы.
- Вкладка SQL Playground показывает заранее заданный запрос и не является SQL-редактором;
  её таблица не зависит от фильтров основного дашборда.
